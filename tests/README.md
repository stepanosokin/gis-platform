# Тестирование

Правила размещения тестов и результатов, а также выбора уровня проверок: [AGENTS.md](../AGENTS.md).

## Публикация GeoJSON через Features

Согласованный уровень для задачи #14 — средний. Пять сценариев проверяют публичный CLI, семь проверяют выдачу через Caddy на реальном стеке Compose.

```sh
npm ci
npm test
```

Тесты CLI, проверка типов и HTTP-утверждения выполняются в Docker. Локальный Node.js запускает команды Compose через CLI платформы. Для каждого прогона используется отдельный проект Compose и свободный порт. В конце его контейнеры и тома удаляются.

`npm test -- --cli` запускает только проверки CLI. `npm test -- --smoke` запускает сквозной сценарий от применения YAML до чтения объекта через Caddy. Логи, копию примера и рабочие файлы прогона можно найти в `test_results/issue-14-*/`.

### Диагностика Docker

Перед сквозным прогоном проверь доступ к движку командой `docker info --format '{{.ServerVersion}}'`. Для отдельного прогона из WSL проверь через `wsl --list --verbose`, что доступен пользовательский дистрибутив и в нём работает Docker. Результат запуска из PowerShell указывай как прогон с Docker Desktop.

При сбое `config apply` сначала открой `apply.log` в каталоге прогона. Откат может удалить контейнеры раньше, чем тестовый сценарий соберёт `stack-services.log`. Если нужны логи запуска, используй копию GeoJSON и сгенерированные конфиги из `state/plans/<plan-id>/` в отдельном проекте Compose. Сохрани `docker compose logs --no-color` в каталог прогона до удаления контейнеров.
