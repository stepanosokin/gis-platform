# GIS Platform

Термины публикации пространственных данных и доступа к сервисам.

## Language

**Черновик конфигурации**:
Желаемая конфигурация развёртывания, в которой оператор собирает изменения для будущего применения.

**План применения**:
Предложенный переход от исходной версии конфигурации к заданной конфигурации с указанием изменений и их последствий.

**Действующая версия конфигурации**:
Текущая подтверждённая конфигурация развёртывания, которая определяет публикации, их маршруты и правила доступа.

**Публикация сервиса**:
Предоставление одного источника пространственных данных через один API или протокол с собственными правилами доступа и постоянным уникальным идентификатором. Один источник может иметь несколько публикаций с разными правами; переименование сохраняет идентификатор, а после удаления он не передаётся другой публикации.
_Avoid_: Набор данных как синоним публикации.

**Источник публикации**:
Набор пространственных данных, используемый одной или несколькими публикациями. Источник сам по себе не задаёт протокол публикации и правила доступа.

**Подключение к PostGIS**:
Именованный способ доступа GIS Platform к одной внешней базе данных PostGIS. Источник PostGIS использует одно подключение, которым могут пользоваться и другие источники.

**Архив тайлов**:
Файл с готовыми растровыми или векторными тайлами, которые адресуются по координатам тайловой сетки. В GIS Platform архив тайлов может быть источником публикации.

**Сервис-провайдер**:
Подключаемый к GIS Platform программный компонент, который обслуживает публикации через один или несколько поддерживаемых им API или протоколов.

**Экземпляр сервис-провайдера**:
Отдельно настроенное подключение сервис-провайдера к GIS Platform со своим идентификатором. Каждая публикация явно указывает экземпляр, который её обслуживает.

**Публичный адрес развёртывания**:
Единый адрес, по которому клиенты обращаются к развёртыванию GIS Platform и на который ведут ссылки платформы.

**Публичный префикс экземпляра**:
Часть внешнего адреса, которая однозначно указывает на экземпляр сервис-провайдера. Под этим префиксом у каждого протокола экземпляра свой публичный корень.

**Страница экземпляра сервис-провайдера**:
Страница по публичному префиксу экземпляра со ссылками на его протоколы.

**Адаптер сервис-провайдера**:
Код интеграции с конкретным сервис-провайдером, который помогает ему соблюдать контракт публикации GIS Platform.

**Динамическая публикация**:
Публикация сервиса, отражающая изменения исходных данных без повторной ручной публикации, с согласованной допустимой задержкой обновления.

**Допустимая задержка обновления**:
Максимальное время между подтверждённым изменением данных источника и моментом, начиная с которого новые запросы к публикации должны получать актуальные данные.

**Задержка подготовки источника**:
Максимальное время между подтверждённым изменением исходных данных и доступностью этого изменения в подготовленном источнике, который читает публикация. Входит в допустимую задержку обновления публикации.

**Сеточные данные**:
В рамках проекта — пространственные данные, представленные сеткой DGGS H3.
_Avoid_: Научные сетки и NetCDF как значение этого термина в текущем объёме проекта.

**Публичный сервис**:
Публикация, доступная всем, включая анонимных пользователей.

**Сервис по регистрации**:
Публикация, доступная всем зарегистрированным пользователям с подтверждённым email.

**Закрытый сервис**:
Публикация, доступная зарегистрированным пользователям с подтверждённым email по персональному разрешению, а также администраторам.

**Персональный токен**:
Именованный секрет для доступа к публикациям от имени конкретного пользователя. У пользователя может быть несколько токенов, каждый с независимым отзывом.

**Администратор**:
Пользователь с правом управления учётными записями и доступом, имеющий доступ ко всем публикациям.

**Email пользователя**:
Уникальный неизменяемый адрес электронной почты, используемый для входа в платформу. Подтверждение владения адресом обязательно для доступа от имени пользователя.

**Отображаемое имя**:
Имя пользователя для отображения в интерфейсе и отчётах. Может повторяться у разных пользователей и изменяться; для входа используется email.
